# 下载与镜像

hello-openttd 所有下载（游戏版本、模组）都经过同一个下载引擎：**自动选择最优源、断点续传、SHA-256 校验**。

## 工作方式

1. **候选源列表**：GitHub 官方源 + 你启用的自定义镜像。
2. **测速**：下载前对候选源做轻量探测（请求时延 + 小样本吞吐，结果缓存约 10 分钟）。
3. **选择**：默认策略下自动选择最快可用的源；失败自动降级到下一个。
4. **校验**：下载完成后进行 SHA-256 校验，通过才进入解压/安装。

## 镜像策略

在 **设置 → 下载与镜像** 中选择：

| 策略 | 行为 |
|------|------|
| 自动（默认） | 每次下载前测速选优，失败自动回退官方源 |
| 最快优先 | 使用最近一次测速的冠军镜像 |
| 固定镜像 | 始终使用指定镜像，失败回退 |
| 仅官方源 | 跳过所有镜像，直连 GitHub |

## 添加自定义镜像

**设置 → 下载与镜像 → 添加镜像**。填入名称与 URL 模板。

镜像模板使用 `{url}` 占位符，启动器会把 GitHub 资源的完整 URL 替换进去。常见的"前缀型" GitHub 加速服务这样填：

```text
https://ghfast.net/{url}
```

也支持"改写型"模板（镜像站用自有路径代理 GitHub 文件）：

```text
https://mirror.example.com/github/{owner}/{repo}/releases/download/{tag}/{asset}
```

注意事项：

- 仅接受 **HTTPS** 镜像；`{url}` 替换值在拼接后仍会做合法性校验。
- ⚠️ **镜像质量参差**：曾有公共加速域名（如 ghproxy.com）易主后对所有请求返回 HTTP 200 的 HTML 页面，静默损坏下载。hello-openttd 的防线：默认镜像列表只内置经过验证的源（直连 + ghfast.net），下载前做 **magic-byte 校验**，任何伪装成压缩包的 HTML 都会在解压前被拒绝；SHA-256 校验进一步兜底。
- 镜像只影响**文件下载**；GitHub API（版本列表）默认直连 `api.github.com`，如有需要可在设置中另行配置。
- 未登录状态下 GitHub API 有每小时 60 次的限额；如需更高限额，可在设置中提供个人访问令牌（PAT，仅保存在本地）。

## 断点续传

- 下载进度保存在 `cache/downloads/`（`.part` 数据 + `.meta` 元数据）。
- 中断后（网络波动、程序退出）可从已完成的字节继续，不必重新下载。
- 若远端文件发生变化（ETag/长度不一致），分片会被丢弃并重新开始，避免拼出损坏文件。

## 文件校验

| 资产 | 校验方式 |
|------|----------|
| 内置版本源的知名发布 | 优先使用版本源注册表/发布方提供的 SHA-256 |
| 带 `sha256` 字段的自定义源资产 | 强制校验，不匹配即失败 |
| 无校验和的资产 | 下载后计算并记录实际哈希（写入版本清单），安装界面明确提示"未验证" |
| 启动器自身发布 | Releases 附带 `sha256sums.txt` |

校验失败一律 **fail-closed**：不安装、不运行，并保留日志供排查。

## 隐私

启动器**不包含任何遥测**。仅在你主动触发下载/刷新时访问版本源、镜像与 BaNaNaS 服务；诊断信息只保存在本地日志。
