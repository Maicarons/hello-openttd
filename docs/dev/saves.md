# 存档服务规格

`services/saves/` 提供存档的扫描、元数据、导入导出与备份恢复。

## 1. 扫描范围

| 目录 | 内容 |
|------|------|
| `<版本目录>/save/` | 手动存档 `.sav` |
| `…/save/autosave/` | 自动存档 |
| `…/scenario/` | 场景 `.scn` |
| `…/heightmap/` | 高度图 `.png` |

独立模式扫描版本目录；共享模式扫描共享目录。另支持"外部目录"临时挂载（浏览但不默认写入）。

## 2. 元数据（分级实现）

- **v1（M6 交付）**：文件系统元数据——文件名、大小、修改时间、相对目录。搜索=文件名匹配；排序=时间/大小/名称。
- **v2（尽力而为）**：解析 `.sav` 头部获得游戏内日期、存档格式版本等。实现要点：
  - OpenTTD 存档为自研 LZ 压缩容器，头部含 magic 与版本字段；
  - 解析失败（版本差异/损坏）**静默降级**为 v1 展示，绝不影响列表可用性；
  - 深度解析进 Isolate，带超时（单文件 ≤ 200ms）。
  - v2 落地前需对照 OpenTTD 源码（`saveload/`）核实头部布局，届时在本文补记字节级规格。

## 3. 导入 / 导出 / 删除

| 操作 | 规则 |
|------|------|
| 导入 | 仅允许 `.sav/.scn` 后缀；重名 → 自动追加序号或用户确认覆盖；复制（非移动），源文件不动 |
| 导出 | 复制到用户选择目录；多选打包 zip |
| 重命名 | 校验文件名字符集（见安全设计）；拒绝路径分隔符 |
| 删除 | 进系统回收站（三平台各自的 trash 机制或启动器内 `.trash/` 暂存），30 天后清理 |

## 4. 备份

**归档格式**：zip，结构：

```
backup-20260913-120000.zip
├── manifest.json        # 时间、来源版本、文件清单+各自 sha256、启动器版本
└── files/
    └── save/…           # 保持相对目录结构
```

- **触发**：手动 / 启动游戏前（可配置）/ 每日首次。
- **保留策略**：最多 N 份（默认 20，可配），超出删最旧；删除前有审计日志。
- **存放**：`<数据根目录>/shared/backups/`——独立于版本目录，卸载版本不删备份。

**恢复**：

1. 校验 zip 内 `manifest.json` 与各文件 sha256；
2. 目标位置同名文件先做"安全备份"（一份自动 bak）；
3. 解包覆盖 → 完成。恢复可跨版本（目标=任一已装版本的存档目录）。

## 5. 性能

- 扫描异步（目录枚举 + `stat`），万级文件延迟 < 1s；>5000 项转 Isolate。
- 列表虚拟滚动（`ListView.builder`）。
- 备份压缩在 Isolate 进行，进度条反馈。

## 6. 测试要点

- 备份往返：备份 → 篡改一个文件 → 恢复时校验失败路径。
- 大量小文件的扫描性能基准（回归护栏）。
- 文件名校验 fuzz（Unicode、路径分隔符、Windows 保留名 CON/NUL…）。
